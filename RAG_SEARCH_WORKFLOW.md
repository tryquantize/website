# RAG Search Workflow - Complete Data Flow

## Overview

This document explains the complete workflow of how the RAG (Retrieval-Augmented Generation) search works and how company cards are populated with data from various sources.

## 1. Search Initiation (Frontend)

**Location**: `apps/web/src/components/search-interface.tsx`

When a user types a query and hits search:
- **Query Processing**: The search query is captured along with filters (types, locations, web search toggle)
- **Authentication Check**: System checks if user is logged in
- **API Call**: Makes POST request to `/api/search` with:
  ```typescript
  {
    query: "user search query",
    userId: user?.id,
    selectedModel: "GPT-4o Mini", 
    selectedTypes: ["company", "product"],
    selectedLocations: ["San Francisco", "New York"],
    webSearchEnabled: true/false
  }
  ```

## 2. Backend API Processing (Express)

**Location**: `apps/api/src/routes/routes.ts`

The Express server receives the search request:
- **Route Handler**: `/api/search` POST endpoint processes the request
- **Data Extraction**: Extracts query, user context, model selection, filters
- **Search Recording**: Records search in storage for analytics
- **AI Service Call**: Forwards request to Python Flask AI service at `http://localhost:5002/search`

## 3. AI Service Decision Logic (Python Flask)

**Location**: `apps/ai-service/app.py` → `src/services/ai_agent.py`

The AI service makes a critical decision based on `webSearchEnabled` flag:

### Path A: RAG-Only Search (webSearchEnabled = false)
**Location**: `apps/ai-service/src/rag/services/rag_search.py`

When web search is disabled, uses pure RAG (Retrieval-Augmented Generation):

1. **Data Loading**: 
   - `DataLoader` loads all company data from `rag/companies/` folders
   - Each company has structured files: `company_info.txt`, `features.txt`, `pricing.txt`, `use_cases.txt`, etc.
   - Data is loaded into memory on service startup

2. **Text Matching**:
   - `TextMatcher` performs fuzzy matching against company descriptions, features, and use cases
   - Uses similarity scoring to find relevant companies
   - Applies type filters (company/product/freelancer) and location filters

3. **LLM Enrichment**:
   - `LLMEnricher` uses OpenRouter API to enhance raw RAG data
   - Generates enhanced descriptions, key specifications, and use cases
   - Creates coherent AI response based on matched companies

### Path B: Web Search (webSearchEnabled = true)
**Location**: `apps/ai-service/src/services/exa_search.py`

When web search is enabled:

1. **Exa API Integration**:
   - Calls Exa search API with enhanced queries
   - Includes location filters in search terms
   - Searches specific domains based on content type (TechCrunch, Crunchbase, etc.)

2. **Real-time Data Retrieval**:
   - Gets current web information about companies and products
   - Extracts titles, URLs, and content snippets
   - Creates citation references for sources

3. **LLM Processing**:
   - Sends web search results to OpenRouter LLM
   - LLM extracts structured company information from web content
   - Generates AI response with proper citations

## 4. Company Card Data Generation

The company cards displayed in the UI get their data from different sources depending on the search mode:

### RAG Mode Company Data Sources:

Each company card field is populated from specific RAG files:

- **Basic Info**: From `company_info.txt`
  - Company name, description, website, category, headquarters, founded year

- **Features**: From `features.txt` 
  - Bullet-pointed list of key features and capabilities

- **Pricing**: From `pricing.txt`
  - Pricing models, ranges, and specific pricing information

- **Enhanced Fields**: Generated by LLM from RAG data
  - **Key Specifications**: LLM processes `features.txt` and `use_cases.txt` to create 5 key specs
  - **Enhanced About**: LLM creates comprehensive paragraph from all company data
  - **Enhanced Use Cases**: LLM generates specific use cases from `use_cases.txt` and industries data

- **Additional Fields**: From structured data in `company_info.txt`
  - Location, employees, company stage, industries served, products/services
  - Top clients (from `clients.txt`), phone, LinkedIn URL

### Web Search Mode Company Data Sources:

- **Real-time Extraction**: LLM extracts company information directly from web search results
- **Company Enrichment**: `CompanyEnrichmentAgent` enhances web-extracted data with additional details
- **Fallback Data**: If extraction fails, uses predefined fallback companies

## 5. Company Card Display Logic

**Location**: `apps/web/src/components/company-cards.tsx`

The company cards component receives the structured data and displays:

### Card Structure:
- **Header**: Company name, logo, category badge, social links
- **Info Grid**: Location, employees, founded year, company stage  
- **Industries Served**: Expandable list with "show more" functionality
- **Products & Services**: Expandable list of offerings
- **Key Specifications**: 5 key technical/business specs
- **Pricing Information**: Pricing ranges and models with colored badges
- **Interactive Elements**: Favorite button, compare toggle, website links

## 6. LLM Usage Throughout the Pipeline

The system uses LLMs (via OpenRouter) at multiple stages:

1. **RAG Enhancement**: Enriches raw company data into user-friendly descriptions
2. **Web Search Processing**: Extracts structured data from unstructured web content  
3. **Response Generation**: Creates coherent AI responses explaining search results
4. **Suggestion Generation**: Creates related search suggestions
5. **Company Comparison**: Generates comparative analysis when users compare companies

## 7. Data Sources Summary

- **RAG Mode**: Pre-curated company data stored in structured text files
- **Web Search Mode**: Real-time data from Exa API + web sources
- **Fallback Data**: Hardcoded company information when APIs fail
- **User Context**: Authentication, preferences, search history
- **Enhanced Fields**: LLM-generated content based on raw data
